# 適度節省用量：重用已核成果，保留品質關卡

目的：減少無意義的重新閱讀、重複交接與整書重做；不承諾固定省量比例。本文是工作排程與證據重用政策，不能減免逐批完整來源閱讀、首次獨立內容核驗、每冊最終逐頁視覺檢查或100頁限制。

## 讀取與派工前先查索引

1. 主代理只讀progress、任務索引、當前章的術語／相依摘要及未解項目。規範按階段載入：來源子任務不需要整份排版手冊；排版任務不需所有閱讀交接。詳細規範保存在repo，只有相關階段讀入。硬性約束與該任務所需規範仍需提供，不以省量為由漏傳。
2. 每個來源小節有一個主要閱讀任務。它同時完成讀字／看圖、段落定位、摘要、術語、符號、公式與圖表清單；不要把同一區段另派五個代理各讀一遍。同一概念在別章重現，引用已核定義及來源ID，必要時只查新增條件。
3. 建立 `tasks/index.json`，逐項記task_id、kind、unit_ids、status、handoff_path、receipt_path、dependency_refs、reuse_reason／rerun_reason及下一步。主代理為唯一索引寫入者，子代理只寫自己的任務目錄。
4. 派工或中斷續作前，先查任務是否已有可接受、證據完整且仍有效的交接。若有就整合／續接，不再次完整閱讀。只找到摘要、沒有原頁證據或資料不可信時，不能把它當成已讀。

## 有界子代理與交接

依完整小節拆批，一般5–10頁，避免一頁一個代理，也不要為節省而把整章塞成巨大任務。預設先安排約2–4個互不重複的可獨立批次，依實際槽位、延遲、內容密度及待整合量調整；這是排程建議，**不改repo的15條上限、模型或effort設定**。不要常駐啟動15個代理等工作。

只有需要保留同小節推理時才續用原子代理；新章／無關任務用乾淨的有界上下文。宿主支援最小上下文派工時使用；不支持就縮小任務輸入，不聲稱能控制宿主沒有暴露的功能。不要自動繼承全書聊天／全部規範／全部原文。主代理的medium/high依原政策，不為省量降掉推導疑點及終審判斷。

來源交接只回摘要、穩定物件ID、檔案路徑及疑點；長證據落盤供按需讀取。核驗交接以新增差異／錯誤清單為主，不整段重貼原文或整份章稿。所有公式、原圖及原題條件仍存可回查檔案，摘要短不代表省略證據。

## 重用憑據與變更失效

主代理接受真實交接後，可用 `scripts/reuse.py` 保存該任務的檔案指紋，續作先check。它只檢查檔案一致，**不能判定已讀、推導正確或依賴列得完整**。來源／教學／PDF關卡仍照常通過。

handoff.json供重用工具讀取的最少欄位：

```json
{"task_id":"read-ch03-s02", "status":"ready", "issues":[],
 "source_sha256":"實際來源SHA-256", "unit_ids":["u0041","u0042"]}
```

其餘逐頁證據、物件清單等仍依協作契約保存。以下命令路徑皆相對書籍專案根；Python用目前平台的venv解譯器。**先實際審閱，再seal**，不要為取得可重用狀態而只填ready。

```text
python <skill>/scripts/reuse.py seal <專案> --task read-ch03-s02 --kind reading --units u0041 u0042 --output tasks/read-ch03-s02/evidence.md --output tasks/read-ch03-s02/inventory-fragment.json --output tasks/read-ch03-s02/terms.json
python <skill>/scripts/reuse.py check <專案> --task read-ch03-s02
```

核驗任務用 `--kind verification`，`--input`逐一列該段稿件、被input的公式、圖檔、已使用的前置定義／符號片段及可執行驗算程式，`--output`列實際核驗報告／輸出。不能只登章稿而漏掉它引用的公式。範圍、學習目標或核驗要求若變了，即使檔案相同也須由主代理判定失效，更新任務，不受工具「相同」結果拘束。

| 變更 | 必須重新處理 | 可以保留 |
|---|---|---|
| 原書／版次／原檔SHA改變 | 先比對來源，重建受影響定位與依賴；工具一律拒絕直接重用 | 舊成果可參考，核對後才重新接受 |
| 某頁抽字、圖片或頁碼定位更正 | 該頁及受影響的相依任務 | 未受影響頁面的有效交接 |
| 定義／符號／假設／公式／題幹／數值變動 | 該物件、引用它的推導／解答與教學核驗 | 無依賴的其他章節 |
| 純文字錯字／版面變動 | 檢查實際差異、相關鎖與受影響冊的編譯／最終全頁視覺QA | 原文未變的閱讀交接及無關數學驗算 |
| PDF重新編譯 | 該冊所有最終PDF視覺紀錄重新取得 | 仍有效的來源／教學內容證據 |

重用收據不能自動覆蓋；重做先保存舊收據、記原因，再真實補核並建立新收據。不因某個任務失效，就重讀整本書；也不能因收據有效而略過發現的新疑點。現有內容鎖需依正式重鎖流程重建；PDF指紋保守失效時不能手改指紋來迴避檢查。

## 首次核驗與本機工具

每份保留的正式內容仍有一次獨立來源對照，重要公式、推導、選入題目及圖表逐項核驗；不改成抽樣。閱讀、編寫、核驗的合理角色分離不能被「避免重讀」取消。原書完整閱讀後，核驗代理只取得指定原頁、指定稿件、依賴與疑點，不重新把全書讀一次。

抽字、頁數、SHA、題號對帳、單位／符號運算、編譯與log篩選由本機程式完成；只把統計、錯誤位置、短差異及檔案路徑送回模型。長log留磁碟，錯誤修復後只重查受影響項；沒有新失敗／修改就不反覆跑同一整套測試。不為確定性小操作另派代理。原圖抽取／驗算結果可重用，但來源與輸入指紋必須一致。

外部查證按疑點查一次，保存URL、查證日期、原書位置及結論；同一穩定疑點不每章重搜。有衝突、新版資料或時效性問題時重新查證。保留原圖優先，避免不必要的AI生圖與重繪。

## 使用量紀錄

可在 `usage-log.jsonl`記工作階段、章／批次、模型與可觀察effort、開始／結束時間、5h／週額度讀值、是否跨重置、來源及產出頁數、重用／重做原因。宿主無法取得的數值寫null，不猜tokens或宣稱有固定省量比例；跨重置讀值不能直接相減。這是觀察工具，不自動更換模型或設定額外付費。接近額度時先保存續點，依宿主可用能力續作。
