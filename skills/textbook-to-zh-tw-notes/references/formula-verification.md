# 公式辨識、獨立核算與修訂閉環

本規範配合[Codex品質基準](codex-quality-baseline.md)、[資料契約](contracts.md)及[核驗提示](../../../prompts/verifier.md)。目的在降低轉錄、約定、代數、代值及排版錯誤，並讓未完成與過期核驗無法冒充完成；機器不判定物理真偽，不能承諾零公式錯誤。

## 1. 先固定約定，才讀公式

每章在正式正文附近交代實際需要的約定，在 `verification.md` 保存可搜尋的「符號約定」錨點及變更對照。不要為每章套用不相干的高階欄位。

| 類型 | 要明示並核對的內容 |
|---|---|
| 座標／觀察者 | 時間是座標時間或誰的固有時、微分對哪個參數、座標適用域、正方向 |
| 單位 | SI、Gaussian或幾何單位；G/c/ℏ是否設1；恢復物理單位的轉換。不得把自然單位下量綱檢查寫成SI已通過 |
| 張量／幾何（若適用） | 度規號誌、曲率定義、指標順序、升降規則、定向／法向、體積元、交叉項係數與分量的因子2 |
| 參數／歸一化 | 總能量或單位質量能量、長度或無因次參數、固定量、同名符號跨章改義時的轉換 |
| 定義域／近似 | 分母非零、根的分支、對數域、小參數、保留階數、邊界／初值、端點另取極限 |

遇到兩式不同先比約定，不能立即以記憶公式覆寫，也不能只因來源有勘誤框就相信修正。

## 2. 四層證據各自完成

**原頁辨識**：看原PDF頁圖及其前後定義，逐字核正負號、上下標、次方、分子分母、括號、縮併指標、上下限及2／π／c等係數。保存原PDF實體頁與印刷頁、原式／圖／題號及頁圖定位，連到來源unit。擷取文字、OCR及搜尋只供導航；無法辨識維持 unresolved，不猜一個看似合理的式子。

**獨立重建**：核驗者先由原頁、前提與題面自行列起點、重要中間步和結果，再與稿件比較。不同的任務上下文即可，同模型並不等於已獨立，換模型也不自動保證正確。作者自查不能充當第二位核驗者；不得把作者結論放進計算程式當預設答案後只印pass。

**交叉檢查**：從下表挑適用方法，保存實際演算或程式、輸入、輸出及判斷。一般核心式／題解應有原頁比對、重算，以及另一項有辨識力的檢查。每項不適用須具體說明，不能全部填N/A湊通過。

| 方法 | 有效證據 | 不能聲稱的事 |
|---|---|---|
| 原方程代回 | 計算殘差，連初始／邊界條件、參數及域一起核 | 只比較最後兩式字串相同不算重算 |
| 量綱／單位 | 寫出基本維度及換算，核係數的單位制 | 量綱一致不能排除缺2或正負號 |
| 特殊值／極限 | 寫固定量、方向與退化分支，檢查是否先除零 | 幾個例子不證明一般恆等式；a=0的檢查也看不出只影響非零自旋項的錯誤 |
| 數值復算 | 符號式獨立代值、有效位數／誤差，避開奇點並測近邊界 | 隨機幾點相等不證明全域成立 |
| 守恆／對稱／跡 | 從定義求殘差或不變量、交換參數等 | 不能套用不滿足前提的對稱 |
| CAS符號運算 | 明確假設、變數、分支及殘差，保存可執行腳本和輸出 | simplify為0不證明建模正確或原頁讀對；sqrt(x²)不無條件等於x |

**最終顯示**：內容核驗後才鎖與正式編譯；看最終PDF的分式、符號、跨行與圖表。編譯成功只證明語法可處理，不能替代前面三層。重編後按原規範逐頁檢視全部最終頁。

## 3. 訂正不能跳過核定

疑點先記 `unresolved`／候選：原位置、可見原述、矛盾、可能的約定差異、需要的證據。獨立核驗完成才作「已核定訂正」，列修正前後差異及實際依據；由主代理更新正式公式後，再核受影響推導、題解、公式表、圖說與數值，最後才正式採用。

內部可以探索多個候選；正式讀本不能一面寫「待主代理核定」，一面把候選用作可靠前提。無法解除的核心歧義保持未完成；對非核心數值若依取捨規則不採，說明實際刪節與影響，不將刪掉疑點當成已解決。查第一手來源只為核對／訂正，不擴寫教材。

## 4. 把已完成的核驗綁到檔案

`math-audit.json` 放在**書籍專案根目錄**。`inventory.json` 中已選入 (`covered`／`compressed`) 的 `equation/derivation/example/exercise` 每項都有且只有一筆；合併講解可共用證據錨點，不能漏掉來源ID。概念題仍需獨立概念核對，不硬做無意義的數值運算。

先完成來源清單、選題與正文落點，再執行下列命令產生**pending模板**，由實際完成的核驗補齊。`init` 不覆寫舊檔、不填pass、不自填「已審」雜湊；之後新增物件由主代理加相應pending項，不能重建抹除舊結果。

```text
python <skill>/scripts/math_audit.py init <書籍專案>
python <skill>/scripts/math_audit.py check <書籍專案>
python <skill>/scripts/project.py check <書籍專案> --stage teaching
```

下列是**欄位示意，非有效核驗紀錄**，`<...>` 必須換成真實值。詳細演算留證據檔，JSON不重抄完整教材。

```json
{
  "schema_version": 1,
  "source_sha256": "<source.json的原PDF雜湊>",
  "conventions_ref": {"file": "verification.md", "anchor": "符號約定"},
  "entries": [{
    "item_id": "<inventory中的真實ID>",
    "author": "<作者任務ID>",
    "reviewer": "<另一核驗任務ID>",
    "status": "pass",
    "issues": [],
    "reviewed_files": {
      "content/math/ch02-eq01.tex": "<已核版本的SHA256>",
      "content/chapters/ch02.tex": "<含前置定義與使用條件的版本SHA256>"
    },
    "evidence_files": {"verification.md": "<核驗證據檔SHA256>"},
    "checks": {
      "source_visual": {"status": "pass", "evidence": [{"file": "verification.md", "anchor": "E01原頁辨識"}]},
      "recompute": {"status": "pass", "evidence": [{"file": "verification.md", "anchor": "E01獨立重算"}]},
      "dimension": {"status": "pass", "evidence": [{"file": "verification.md", "anchor": "E01量綱"}]},
      "limit": {"status": "pass", "evidence": [{"file": "verification.md", "anchor": "E01固定參數極限"}]},
      "domain": {"status": "pass", "evidence": [{"file": "verification.md", "anchor": "E01定義域"}]}
    }
  }]
}
```

每個pass必須有存在的檔案／錨點；引用檔須列入 `evidence_files` 並固定實際SHA，包含 `conventions_ref`。程式和其實際輸出也放入此雜湊表，即使錨點在說明檔。所有路徑相對專案根、不得越界。`reviewed_files` 至少涵蓋該來源物件的所有 `output_refs` 檔案，另列會影響公式含義的前置定義與共用公式；程式不能自動知道語意依賴，主代理必須補全。

`source_visual` 不可免核。`equation`／`derivation` 的 `recompute` 不可免核。純概念的 `example`／`exercise` 可設 `recompute.status=not_applicable` 並填 `reason`，但需另有 `conceptual` pass及證據。`dimension/limit/domain` 不適用時填 `status=not_applicable` 與具體 `reason`。僅有「不適用」四字不支持人工接受。

舊專案第一次用新工具：沿用真實有效的來源與核驗證據，補齊此ledger，不重新讀未變全書，也不因舊版未記錄就捏造核驗。既有核驗若無法證實、缺原頁辨識或沒有實算，補做對應物件後再正式交付。沒有選入上述物件的專案可不建ledger。

## 5. 變更如何使舊審查失效

`project.py` 的 teaching 關卡自動檢查ledger；全書 compile／prepare-review／check沿用此關卡。內容鎖包含ledger及所列稿件／證據現況指紋；每次核對ledger都重算所列正文、定義及證據檔SHA。漏項、重複ID、未知ID、未解問題、同作者／核驗者、失效雜湊、缺錨點或不合法路徑都阻擋通過。此工具不執行JSON中的程式或指令。

正文、公式或約定變更後，先將受影響物件標pending，列下游依賴，實際複核後再更新hash。不能只重算所有雜湊就宣稱重審；證據檔增加新小節造成hash改變時，先核差異，保留未受影響的演算並由主代理接受，再更新引用的證據版本。可將不同物件證據拆在專屬檔以避免無關變更。

最後保存舊鎖與修訂理由，通過teaching再重鎖／重編／prepare-review／逐頁檢查。工具不能防止人同時捏造所有紀錄，也不能證明作者／核驗任務真的不同；真實看圖、推理與執行紀錄仍是必要的責任。
