# 可選分工：Muse閱讀，Codex寫作與排版

當使用者採用此分工時，Muse負責原書完整閱讀及來源紀錄，Codex負責教學取捨、連貫中文、正文／題解、公式整合與排版。這是現有規範的可選角色安排，不修改使用者的模型／供應商設定，也不要求兩個工具自動共用聊天上下文。

## Muse交付可回查的來源包

先建立原PDF身分、SHA、完整目錄及雙頁碼對照，再按完整小節分批閱讀原頁文字和圖像。每批只寫專屬tasks/muse-read-章節/，交付：

- 原書小節、實際PDF頁序、可辨印刷頁、來源unit及讀字／看圖紀錄。
- 概念的原始論證順序、假設、限制、反例與精確定位。
- 完整可編輯LaTeX公式、符號定義、單位制、正方向、參數／觀察者、定義域與關鍵原書推導步驟；不能只有公式名稱。
- 實際原圖裁切檔及圖號、圖說、軸、單位、圖例和用途，不能只有圖片描述。
- 原題題號、完整必要條件及所有小問，原書是否真的提供答案；已有解答和Muse計算分開記。
- 術語與符號清單、相依前章、疑點及訂正候選，附實際查核／計算證據。
- 有索引的handoff、evidence與inventory-fragment，標ready或needs_followup；ready只表示本批交付，不表示教學或全書通過。

來源包沿用Skill的[來源契約](../skills/textbook-to-zh-tw-notes/references/contracts.md)及[閱讀提示](../prompts/source-reader.md)。摘要作導航，不替代原式、圖、題及原頁證據。資料完整性不足時由Muse補對應物件；不必再生一版壓縮講義給Codex接著潤稿。

## Codex接受來源後重新組織正文

將同一份書籍專案及原PDF路徑交給Codex，並指明已完成批次與尚未完成批次。Codex先核對原檔版本、目錄、交接範圍與證據，再按需要局部回查原頁；重要公式與題解獨立復算，不把Muse的「已確認」直接視為通過。

Codex依[中文解釋規範](../skills/textbook-to-zh-tw-notes/references/prose-and-explanation.md)和[逐章提示](../prompts/write-chapter.md)由原始證據寫正文，明確建立概念、推理、實際計算與結果解讀，再整合原圖、章末題解及版面。來源忠實性、教學可讀性、數學核驗與最終PDF檢查仍各自完成；另外的核驗任務可使用同模型，但需要獨立的任務上下文與實際計算。

已接受且版本未變的閱讀證據可重用；不因換工具就重新全文讀取原書，也不將整書原文載入主代理上下文。若資料夾跨平台搬移，依原PDF的SHA重新定位，不能照抄舊Linux路徑、內容鎖或pass。

## 每批都能交接，權威檔只有一位寫入者

不必等整本讀完才開始寫。Muse完成一批、Codex接受一批後，Muse可讀下一批，Codex寫前一批。已交付的來源包固定版本，修改則另存修訂並通知Codex。

開始寫作後，由Codex作為正式content、book／inventory／coverage／qa、共用術語、內容鎖與最終交付的唯一整合者；Muse不與Codex同時覆寫這些權威檔。新讀取內容先留專屬任務包，由Codex接受合併。來源初次建檔與正式接手的時間點記在progress。

## 使用者看到的成品

直接嵌入實際照片／原圖；正文只寫教材，不列學習目標、先備清單、作者檢查點或內部交接語。訂正採用結果直接整合，過程記logs/corrections.md。冊數依使用者指定，未指定預設2–4冊；每冊全部PDF頁面最多100頁。最後交付各冊PDF、可編輯LaTeX、來源對照、取捨清單、訂正log及品質報告。

這種分工能保留完整閱讀成果並讓Codex掌握正文品質；來源辨識和計算仍可能出錯，因此可回查證據與獨立核算不能省略。本指南未宣稱已完成Muse→Codex的整書實機評測。
